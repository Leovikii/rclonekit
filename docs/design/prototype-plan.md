# Windows 原型方案

日期：2026-11-12；默认参数与移动网络策略更新：2026-11-18。状态：已完成 [0.1.0-dev.1 前端开发版](../development/0.1.0-dev.1.md)，真实系统集成待实施。

## 目标与范围

RcloneKit 提供接近 Windows 网络驱动器的体验：完成必要组件安装后，填写地址、选盘符、连接；主页用卡片管理多个连接。首轮先验证 Windows 界面，保留 Linux 的平台接口。

已经确认：设置集中安装、卡片主页与新增卡片、可选凭据、高级选项折叠、推荐默认值、超时与断网处理、关闭 GUI 后挂载继续。后续聊天已选择每个挂载对应原生 Windows 服务，覆盖早期 GUI 子进程/托盘方案。本聊天进一步收敛：只向用户展示是否已挂载，不常驻展开复杂运行状态。

已确认：首版仅 WebDAV，不显示连接类型选择；这与“地址 + 可选用户名密码”最匹配。连接模型保留明确类型，SFTP、OAuth 等在确有需求时扩展，不能把任意 HTTPS 地址自动断言为 WebDAV。

第一开发版本按下述 UI 工程阶段交付，采用模拟接口，不注册服务、不读取真实凭据、不连接远端。用户要求首版保持简单，正式版推出前不构建安装包或单独测试程序；必要的源码与浏览器测试由 agent 执行。

## 两页与三个必要流程

| 场景 | 页面与行为 |
| --- | --- |
| 首次检查 | 主页短暂显示“正在检查组件”；检测失败显示重试，不误判为未安装 |
| 缺少组件 | 主页只显示“完成安装后即可连接网络驱动器”与“前往设置”；已保存配置保留，不因缺组件删除 |
| 安装组件 | 设置显示 rclone / WinFsp 的版本和真实状态；一个“安装所需组件”，只安装缺失项 |
| 安装部分失败 | 成功组件保留，说明失败阶段，只重试失败项；需重启时显示“重启后继续” |
| 安装就绪 | 设置提供“开始连接”返回主页，不自动弹出表单；主页显示已有卡片或单张新增卡片 |
| 新增 | 新增卡片打开表单；地址、自动选择的可用盘符、可选身份验证和折叠高级选项 |
| 提交 | 一次“连接”执行校验、限时只读检查、保存配置、注册/启动服务；卡片显示连接进度 |
| 失败 | 保留配置及输入，就近显示原因；重试复用同一挂载 ID，不重复注册服务 |
| 日常使用 | 卡片只显示已挂载/未挂载，打开磁盘或安全断开；编辑与删除在更多菜单 |

设置仅保留语言、系统/浅色/深色外观、组件状态与安装、打开日志文件夹和仓库链接。应用自更新单列为后续发布工作，不在本次原型加入没有实现的按钮。语言/外观即时保存，系统操作由明确按钮触发。

### 连接表单

| 字段 | 行为 |
| --- | --- |
| WebDAV 地址 | 必填，例 `https://dav.example.com/dav/`；接受 HTTP/HTTPS，保留子路径；HTTP 明示传输未加密 |
| 盘符 | 自动选择真实空闲盘符，可修改；保留已保存配置的目标，禁止静默换盘 |
| 身份验证 | 可选展开用户名与密码；密码掩码，不回显已保存密码；编辑时空白表示不改，清除须明确操作 |
| 凭据 | 首个开发版不保存，重新连接时按需再次填写；真实服务安全存储待后端验证，不提供保存开关 |
| 高级选项 | 首版仅“只读”；开机连接、自定义缓存及超时等在后续有实际需求时加入 |

首次 UI 不开放任意命令参数、缓存模式组合、服务账户或参数预设选择，不提供无必要的“恢复默认值”按钮。真实后端的缓存目录按稳定挂载 ID 由程序管理；自定义目录需要所有权、服务访问权限和路径校验，暂不开放。

错误表述为“地址无法连接”“用户名或密码不正确”“盘符已被占用”“无法确认驱动器状态”，提供脱敏详情。失败不能吞掉原输入，密码不能进入日志、URL、命令行或预览状态快照。

编辑仅在安全断开后允许；已挂载时菜单说明“请先断开后编辑”，不隐式断开或重启。保存失败不得冒充成功；服务变更失败保留可重试记录，避免留下不可追踪实例。

## 卡片状态与安全断开

主页表达管理状态，不表达远端健康。只保留两个常驻状态：“已挂载”“未挂载”；进行操作时临时显示“正在挂载”“正在断开”。“已挂载”仅表示挂载存在，不暗示服务器一直可达或上传全部完成。

| 展示状态 | 操作与反馈 |
| --- | --- |
| 未挂载 | 连接；更多内编辑、删除配置 |
| 正在挂载 | 临时操作文字，禁止重复连接；只读检查可取消，服务已启动则重新查询结果 |
| 已挂载 | 打开、断开；不附加远端健康、上传统计或运行阶段徽章 |
| 正在断开 | 临时操作文字；完成后回到未挂载，失败则保留已挂载并就地提示 |

首次查询完成前使用短暂加载占位，不先猜测状态。查询失败保留上次已确认值并显示“暂时无法读取挂载状态，重试”，不能凭空标记为未挂载；没有可靠结果时禁用依赖该结果的动作。它是读取失败反馈，不增加一个常驻状态分类。

后台按需保留安全停止所需的信息，UI 不把内部检查逐项展开。远端不可达不会自动改变“已挂载”；用户执行连接或打开等操作失败时，就近显示简短原因。避免为了显示状态持续探测远端。

断开前检查上传队列、打开文件、上传失败与状态新鲜度；有风险则保持运行，提示“仍有文件待上传，稍后再断开”或“无法确认上传状态，请稍后重试”。停止过程需要阻止新访问或验证目标版本的可靠停止机制，不能把单次队列为零当成安全保证。

首版没有强制断开或自动强杀。连接检查与界面等待超时不等于允许杀掉正在上传的服务。关闭应用只关闭 GUI，服务继续；不把挂载继续运行寄托在托盘进程存活。

“删除配置”只在已确认断开、无活动文件和无待上传缓存时允许，确认显示具体盘符与主机。移除自有服务登记及挂载记录，不删远端文件、不清空缓存或默认删除凭据。缓存/凭据的显式清理不属于首版操作。

## 默认值与超时

优先沿用固定版本 rclone / WinFsp 的官方默认值；只有明确的使用场景或缺少适用默认策略时才覆盖，并记录原因、代价与待测条件。生成启动参数时省略沿用默认的选项，不在代码中复制一套官方数值。官方默认是测试基线，不代表官方已验证本项目的 WebDAV、TCP VPN、服务账户或笔记本功耗。

下表的官方数值为 2026-11-18 查阅文档时的参考值；真实后端接入时须固定组件版本，核对该版本帮助与文档，升级时复核默认值变化。当前尚未固定或执行原生组件。

| 设置 | 初始策略 | 依据与限制 |
| --- | --- | --- |
| Windows 挂载方式 | 项目覆盖：`--network-mode` | 符合网络驱动器用途；仅盘符，多挂载的卷/共享名称必须唯一 |
| 缓存 | 项目覆盖：`--vfs-cache-mode full`（官方默认 off） | 满足常见应用读写/定位兼容性并复用已读数据；增加本地磁盘写入，写入成功不等于已上传；按挂载 ID 隔离缓存 |
| 缓存清理目标 | 项目覆盖候选：`--vfs-cache-max-size 10Gi`（官方默认不限制） | 为笔记本缓存提供清理目标，容量仍待磁盘压力测试；不是硬上限，待上传及正在使用的文件不能靠清理目标强删 |
| 建立连接 | 沿用官方 `--contimeout` 默认 1m | 撤回 10s 覆盖，避免未经实测缩短 VPN 恢复窗口 |
| I/O 空闲 | 沿用官方 `--timeout` 默认 5m | 撤回 30s 覆盖；不是整个操作的总时限，彻底断网时文件操作仍可能等待较久 |
| 底层重试 | 沿用官方 `--low-level-retries` 默认 10 | 撤回 2 的覆盖；不是所有网络/文件系统等待的总次数，不据此推导完整等待上限 |
| 缓存保留与清理 | 沿用官方 `--vfs-cache-max-age 1h`、`--vfs-cache-poll-interval 1m` | 不采用此前讨论的 24h / 5m 候选；清理间隔是本地缓存维护，不等于远端探测 |
| 目录缓存与写回 | 沿用官方 `--dir-cache-time 5m`、`--vfs-write-back 5s` | 不为省电盲目延长目录陈旧或待上传时间；目录缓存期限不代表定时遍历远端 |
| 缓冲、预读、分块、并发及远端轮询 | 沿用固定版本官方默认与后端能力 | 不添加吞吐或省电预设，不主动开启递归预热或额外健康探测 |
| 开机连接 | 项目行为：默认关闭 | 保存凭据且安全持久化成功才可开启；不是“启动 GUI” |
| 挂载前检查 | 项目等待预算：独立异步只读任务，总等待约 15s，可取消 | 非 rclone 传输参数；不递归扫描、不阻塞 UI，超时只说明本次检查未完成，不据此认定地址或凭据错误，可重试 |
| 挂载就绪等待 | 项目等待预算：约 30s 后重新核对服务与挂载状态 | 非服务寿命上限；无法确认时就地提示重试查询，不新增常驻状态、不重复创建实例或停止服务 |

网络检查、RC、服务控制的等待预算与 rclone 数据传输超时分开；它们没有可直接套用的产品默认策略，以上数值仍须集成验证。主页不遍历挂载盘、不调用可能卡住的磁盘容量查询作为健康检查；有界后台状态查询失败不妨碍操作其他卡片。

不能承诺远端故障时资源管理器或所有第三方软件零等待。Windows 不使用 Linux 的 `--daemon-timeout`；也不把 `--timeout` 当作 WinFsp 文件请求总时限。

来源：[挂载与 Windows 限制](https://rclone.org/commands/rclone_mount/)、[通用参数](https://rclone.org/docs/)、[服务集成](https://rclone.org/install/#mount-command-built-in-service-integration)、[RC](https://rclone.org/rc/)。

### TCP VPN、局域网与笔记本

同一 WebDAV 地址在局域网直接可达，外出时通过 TCP VPN 访问同一内网服务器；连接路径由系统路由与 VPN 决定。RcloneKit 不切换地址、不识别网络后另建挂载，也不通过周期性 WebDAV 请求替 VPN 保活。

首版保持用户已建立的挂载，关闭 GUI 后服务继续；不加入闲时自动卸载或访问时自动挂载。空闲挂载不等于持续传输，自动卸载的续航收益尚无实测依据；有打开文件、待上传或无法确认状态时不得停止。Windows 没有一个 rclone 原生参数完成这套自动卸载/恢复行为；Linux 的 systemd automount 与 Windows 的 WinFsp Launcher 集成不能视为已验证的首版能力。

不额外阻止系统正常睡眠，不为卡片状态持续探测远端，不在断网或切网时反复重启服务；保留缓存并在用户操作时反馈失败。睡眠/唤醒、VPN 断开/恢复、局域网切换及待上传恢复均须实机验证，不能承诺现有连接无缝迁移、缓存可完全离线使用或具体省电比例。

后续调参按[原生测试基线](verification.md#默认参数与移动场景测试基线)执行；先测基线，确认问题后每次只调整一个参数，保留对照与回退方式，不把讨论中的候选值直接升级为默认。

## 最小架构与系统安全

沿用 Tauri 2 + React + TypeScript + Mantine + 单 Rust crate。前端只处理表单、页面、展示状态和 IPC；Rust 负责校验、配置、凭据、状态、rclone 调用与安全停止；platform 模块集中安装、挂载目标、服务、自启与系统目录。不要先建插件框架、数据库或第二个常驻服务。

| 公共能力 | Windows 首版 | Linux 后续 |
| --- | --- | --- |
| 环境与依赖 | 检测 rclone / WinFsp / WinGet，只装缺失项 | FUSE 与目标发行版包管理器，发行版待定 |
| 挂载目标 | `{ kind: "driveLetter", value: "X:" }` | `{ kind: "directory", value: "/…" }` |
| 生命周期 | 每个挂载一个原生 Windows 服务 | systemd 用户/系统服务按权限需求确定 |
| 数据位置 | 显式配置/缓存/日志路径和 ACL | 遵循 XDG 与服务账户访问权限 |
| 展示能力 | 后端报告支持盘符、依赖安装与开机连接 | 前端依能力渲染，不散落 OS 判断 |

最少接口：读取环境与挂载快照、安装缺失组件、提交连接/编辑、连接已有配置、安全断开、删除配置、打开目标与日志。挂载快照只需稳定 ID、显示字段和是否已挂载；读取失败单独返回错误，不能把失败转换成 false。提交返回稳定挂载 ID 和结构化结果；耗时动作报告可取消能力，详细阶段仅用于任务或诊断；错误含 code/phase/可重试信息，敏感详情留后端。凭据通过单次输入传递，快照只返回“是否已保存”。不为原型造通用命令总线。

数据分为连接信息与挂载设置，使用独立 ID；盘符、地址和服务 PID 都不是配置身份。由应用创建的 rclone 配置独立保存，不覆盖用户既有全局配置；首次不做自动导入或迁移。

Windows 原生服务运行账户与 ACL 是真实挂载的先决条件：

- 为开机运行和会话可见性评估 LocalSystem；不可把默认 Everyone 可读写的挂载直接当成最终方案。限定拥有者 SID 的文件系统/服务控制权限，验证其他普通用户无法访问凭据或远端。
- SYSTEM 可执行文件、启动配置、RC 秘密与依赖加载路径必须位于受保护位置。普通用户可写目录中的 rclone 二进制不能直接注册为 SYSTEM 服务。
- 短时提权仅接受固定业务动作和结构化字段，重新校验调用者、目标路径、归属与参数；不提供任意命令、任意 executable 或任意服务控制通道。
- 服务凭据采用与账户匹配的 Windows 安全存储/加密及 ACL，先实测跨账户读取；rclone obscure 不是安全加密。未验证前不开放真实保存和开机连接。
- RC 仅监听回环，强随机认证，秘密只在后端；只控制有归属记录的实例，不凭 PID 或盘符猜测后结束进程。
- 注册、编辑和删除对挂载 ID 加互斥，并重新验证目标盘符。参数分别传递，不拼 shell 命令；服务启动路径严格引用并保护其目录。
- 正常操作不自动清缓存、不上传日志；日志有界并脱敏。系统安装保留 UAC 和安装器交互，以真实退出及重新检测确认结果。

## 实施与验收顺序

1. 设计稿：本次文档与交互示意，确认卡片和表单密度。
2. Windows UI 工程：Mantine 实现两页、表单、弹窗；模拟接口覆盖全部状态，UI 文案支持中英。此时不添加系统写入能力。
3. 后端只读检测：组件、盘符占用、配置与能力；固定依赖版本及来源，建立脱敏日志。
4. 隔离 Windows 集成：先验证服务账户、受保护路径、ACL、凭据和 RC，再接连接、安全断开、开机连接；未完成不能声称可正式使用。
5. 安装与交付：组件安装失败/重启分支、签名与打包；Linux 平台实现另行验收。

不加入文件浏览器、同步/备份、远端管理页、服务管理页、拖拽排序、分组、批量操作、性能预设、任意参数输入、全后端表单或应用自更新流程。
